# 4.1 比较运算与布尔表达式

## 4.1.1 六个比较运算符

- 先学会“比”：结果是 True 或 False
- 判断相等用 `==`，不等用 `!=`

::: notes
要做判断，先要会“比”。Python 有 6 个比较运算符，比较的结果只有两种：`True`（成立）或 `False`（不成立）。
像 `price > 3` 这样，结果是 `True` 或 `False` 的式子，叫布尔表达式。后面 if 语句里写的“条件”，就是一个布尔表达式。
`>=` 和 ``。
:::

## 4.1.1 六个比较运算符

| 运算符 | 含义 | 例子（`price = 3.5`） | 结果 |
|---|---|---|---|
| `>` | 大于 | `price > 3` | `True` |
| `<` | 小于 | `price < 3` | `False` |
| `>=` | 大于等于 | `price >= 3.5` | `True` |
| `<=` | 小于等于 | `price <= 3` | `False` |
| `==` | 等于 | `price == 3.5` | `True` |
| `!=` | 不等于 | `price != 3.5` | `False` |

## 4.1.2 比较字符串

- `"可乐" == "可乐 "` 是 False：多了空格
- 比较前先 `strip()`
- `"10" < "9"` 是 True：逐个字符比

::: notes
字符串也能比较。`==` 判断两个字符串是否一模一样，多一个空格、大小写不同都不算相等：
所以第 3 章强调，比较之前先用 `strip()` 去空格、用 `lower()` 统一大小写。
字符串之间还能比大小，规则是从第一个字符开始，逐个比较字符的编号（3.6.1 节讲过的 Unicode 编号）：
`"10" < "9"` 结果是 `True`，因为字符串比较是先比第一个字符：`"1"` 的编号比 `"9"` 小，后面就不用比了。这说明：数字一定要先转成数字再比较，用 `input` 得到的字符串直接比大小，结果会出错。
:::

## 4.1.3 连写的比较与小数比较

- `60 <= x < 90` 可以连写
- 小数不要用 `==` 直接比
- 用 `abs(a - b) < 1e-9` 或先 round

::: notes
数学里写“60 ≤ 分数 < 90”，Python 可以几乎照抄：
`60 <= x < 90` 的意思是“`60 <= x` 并且 `x < 90`”，两个都成立才是 `True`。
还记得 2.2.2 节的 `0.1 + 0.2` 不等于 `0.3` 吗？小数有微小误差，所以不要用 `==` 直接比较两个小数，可以先 `round` 再比：

# 4.2 if 语句：让程序做选择

## 4.2 if 语句：让程序做选择

- 默认从上往下执行：**顺序结构**
- if 让程序出现岔路：**分支结构**

::: notes
程序默认从上往下一行一行执行，这叫顺序结构。有了 if 语句，程序可以根据条件决定执行哪些行、跳过哪些行，这叫分支结构。
:::

## 4.2.1 单分支 if

- `if 条件:` 末尾要有**英文冒号**
- 下一行缩进 4 个空格
- 缩进相同的几行是同一个代码块

::: notes
最简单的 if 语句只有一个分支：条件成立就做某件事，不成立就什么也不做。
输入 128 和 86，分别运行两次：
写 if 语句要注意三点：
第 1 章说过，Python 用缩进表示代码的层次。到了 if 语句，缩进就有了真正的作用：它决定了哪些行受条件控制。
:::

## 4.2.2 双分支 if-else

- 条件成立走 if，不成立走 else
- 两条路只走一条

::: notes
条件成立做一件事，不成立做另一件事，用 if-else：
`else` 后面同样要有冒号，它下面的代码也要缩进。`else` 不能单独使用，也不带条件，它的意思就是“否则”。if 和 else 两条路只走一条，而且一定走一条。
:::

## 4.2.3 多分支 if-elif-else

- 从上往下逐个检查条件
- 遇到第一个成立的就执行，其余跳过
- 条件的顺序很重要

!sim branch-flow

::: notes
情况多于两种时，用 if-elif-else。`elif` 是 else if 的缩写，意思是“否则，如果……”。
Python 执行 if-elif-else 的规则是：从上往下逐个判断，遇到第一个成立的条件，就执行它下面的代码，然后跳过剩下的所有分支；如果一个都不成立，就执行 else。
以 75 分为例：75 >= 90 不成立，看下一个；75 >= 80 不成立，再看下一个；75 >= 70 成立，于是 level 设为“中等”，后面的 `elif score >= 60` 和 `else` 都不再看。
你可能会问：第三个条件为什么只写 `score >= 70`，而不写 `70 = 80` 已经不成立了，score 一定小于 80，不用再写一遍。
下面的动画演示程序在不同输入下走了哪条路。点“下一步”，注意被跳过的行不会被高亮。
:::

# 4.3 逻辑运算 and、or、not 与 in

## 4.3.1 and、or、not

- `and`：都成立才成立
- `or`：有一个成立就成立
- `not`：取反

::: notes
现实中的条件常常不止一个。比如“成年并且是会员才能参加抽奖”“满 100 元或者有优惠券都能减钱”。把几个条件组合起来，用逻辑运算符：
可以把 `and` 想成两道门串在一起，两道都开才能过；`or` 是两道门并排，开一道就能过。
:::

## 4.3.1 and、or、not

| 运算符 | 含义 | 什么时候是 True | 例子 |
|---|---|---|---|
| `and` | 并且 | 两边**都**是 True | `age >= 18 and member` |
| `or` | 或者 | 两边**至少一个**是 True | `total >= 100 or coupon` |
| `not` | 不是 | 把 True 变 False，False 变 True | `not member` |

## 4.3.2 优先级

- not 最高，and 其次，or 最低
- 记不住就加括号

::: notes
三个逻辑运算符的优先级是：`not` 最高，`and` 其次，`or` 最低。比较运算符（`>`、`==` 等）又比它们都高。所以：
左边先算 `False and False` 得 False，再算 `True or False` 得 True；右边有括号，先算括号里的 `True or False` 得 True，再算 `True and False` 得 False。
记不住优先级没关系，加括号就行。括号让意思更清楚，别人也更容易读懂。
:::

## 4.3.3 in 和 not in

- `ans in ["y", "Y", "是"]`
- `"芬达" not in "可乐雪碧"` → True

::: notes
第 3 章用过 `in` 判断一段文字是否包含另一段文字，它在 if 语句里非常好用：
这样写，用户输入 `y`、`Y`、`yes`、`是` 都能被识别。不过要注意：`in` 检查的是“是不是其中的一段”，`"es"` 也在 `"yes是"` 里面。第 6 章学了列表以后，可以写成更严格的 `answer in ["y", "yes", "是"]`。
`not in` 是 `in` 的反面：`"芬达" not in "可乐,雪碧,矿泉水"` 的结果是 `True`。
:::

## 4.3.4 什么算“真”，什么算“假”

- 假：False、None、0、空字符串、空列表
- 其他都算真
- `if name:` 即“如果 name 不是空的”

::: notes
if 后面不一定要写比较运算，也可以直接写一个值。Python 会把它当成真或假，这叫真值测试。规则很简单，下面这些值被当作“假”，其余都是“真”：
`if name:` 的意思就是“如果 name 不是空的”。注意 `" "`（一个空格）和 `"0"`、`"False"` 都不是空字符串，它们都是“真”。
:::

## 4.5 常见错误

- `if x = 1:` → 提示 `Maybe you meant '=='`
- 漏写冒号 → `expected ':'`
- 该缩进的没缩进 → IndentationError
- 条件顺序写反 → 不报错但结果错

::: notes
条件判断的代码不长，但很容易写错。下面是编者在 Python 3.14 中运行的真实报错。
错误一：把 `==` 写成 `=`
报错的最后一行已经提示了：“你是不是想写 `==`？”（`:=` 是一种高级写法，本书不用。）
错误二：漏写冒号
“expected ':'” 的意思是“这里应该有一个冒号”。`if`、`elif`、`else` 后面都要有冒号，而且必须是英文冒号；用中文冒号 `：` 同样会报错。
错误三：该缩进的没缩进
意思是：“第 2 行的 if 语句后面，应该有一个缩进的代码块”。
错误四：不该缩进的缩进了
“unexpected indent” 是“意外的缩进”：第 4 行比第 3 行多缩进了两格，Python 不知道它属于哪一层。同一个代码块的每一行，缩进必须完全相同。另外，不要混用 Tab 键和空格，统一用 4 个空格最稳妥（Thonny 按 Tab 键会自动换成 4 个空格）。
错误五：条件顺序写反（不报错，但结果错）
95 分应该是“优秀”，却输出了“及格”。原因是第一个条件 `score >= 60` 已经成立，后面的 elif 根本没机会判断。这种错误不会报错，比前面四种更难发现。规则是：范围从严到宽，按“大于等于”比较时，先写大的数（`>= 90` 在 `>= 60` 前面）；按“小于”比较时，先写小的数。
:::

## 4.6 前沿视窗：AI 是怎样“做判断”的

- 早期 AI：专家写成千上万条规则
- 规则写不完，情况变了要重写
- 机器学习：让程序从数据中自己学规则
- 决策树学出来的就是一串 if-else

::: notes
你可能觉得 if 语句太简单了，跟人工智能扯不上关系。其实，早期的人工智能正是靠成百上千条“如果……那么……”规则工作的。20 世纪 70 年代美国斯坦福大学研制的医疗诊断系统 MYCIN，用大约几百条规则帮助医生判断细菌感染、推荐抗生素。这类系统叫“专家系统”，规则由专家一条条写出来，本质上就是一大串 if 语句。
专家系统的问题是：规则太多写不完，情况一变规则就得改。现在的机器学习换了思路：不再由人写规则，而是让计算机从大量数据中自己“学”出判断方法。比如判断一条顾客评价是好评还是差评，与其写“如果包含‘好吃’就是好评”，不如给模型看几千条标好的评价，让它自己学。第 12 章会用三行代码体验一下。
有意思的是，机器学习里有一种很常用的模型叫决策树，它学出来的结果就是一棵“if-else 树”，学过本章的你完全能看懂。后续的《机器学习》课程会专门介绍它。
不过，在真实的软件里，规则并没有过时。满减、阶梯电价、会员等级这类“规矩明确、不能出错”的事，依然由程序员用 if 语句写成规则；只有“说不清规则”的事，比如认图片、听语音、读懂评价，才交给机器学习。会写清楚的规则，是用好 AI 的基础。
:::
