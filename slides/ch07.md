# 7.1 字典：键值对

## 7.1.1 创建字典与取值

- 花括号，`键: 值`
- `prices = {"可乐": 3.5, "雪碧": 3.0}`
- `prices["可乐"]` → 3.5
- 列表按位置找，字典按名字找

::: notes
字典（Dictionary）用花括号 `{ }` 括起来，里面是一对一对的“键: 值”，叫键值对：
这里“可乐”是键，3.5 是值。键就像字典里的“字”，值就是它的“解释”。取值时，把键写在方括号里：
`len` 得到键值对的个数。用一个不存在的键取值，报 `KeyError`（键错误）。
和列表比一比：列表用位置（0、1、2……）找数据，字典用名字找数据。名字比位置好记得多，而且不管字典有多大，按键查找都几乎一样快。
:::

## 7.1.2 增加、修改与删除

- `d[键] = 值`：没有就增加，有就修改
- `d.pop(键)`、`del d[键]` 删除

::: notes
增加和修改是同一个写法 `字典[键] = 值`：键不存在就新增，键已存在就修改。删除用 `pop(键)`（返回被删的值）或 `del 字典[键]`。
:::

## 7.1.3 get：查不到也不报错

- `d["雪碧"]` 查不到报 KeyError
- `d.get("雪碧", 0)` 查不到返回 0

::: notes
为了不让程序因为 KeyError 崩溃，可以先用 `in` 判断键在不在，或者用 `get` 方法：
`get(键, 默认值)` 是字典最有用的方法之一，7.2 节的词频统计全靠它。
:::

## 7.1.4 键的规则

- 键不能重复，后写的覆盖先写的
- 键必须是不可修改的类型：字符串、数字、元组
- 字典记住加入的顺序

# 7.3 字典和列表嵌套

## 7.3.1 一条记录是一个字典

- `{"会员号": "M001", "姓名": "周洋", "积分": 693}`
- 比列表更清楚：按名字取字段

::: notes
字典不只能存“名字→价格”这种一对一的关系，还很适合存放一条记录的各个字段：
比起列表 `["M001", "周洋", 693]`，用 `member["姓名"]` 比 `member[1]` 好懂得多，不用记“姓名是第几个”。
:::

## 7.3.2 一张表是字典的列表

- 多条记录放进列表
- 列表里装字典，就是 JSON 的样子
- 数据均为虚构

::: notes
多条记录放进一个列表，就是一张表：
（会员信息均为虚构。）`sum(m["积分"] for m in members)` 和列表推导式类似，是把每个会员的积分取出来求和。
这种“列表里装字典、字典里还可以再装列表”的结构，就是互联网上最常用的数据格式 JSON 的样子。手机 App 和服务器之间、你的程序和大模型之间传递的数据，大多是 JSON。第 9 章学习把它存成文件，第 12 章读取大模型返回的 JSON。
:::

# 7.4 集合：去重与交集、并集、差集

## 7.4.1 创建集合与去重

- 花括号，只有值没有键
- 重复的元素自动只留一个
- 没有顺序，不能用索引
- `add` 加入，`discard` 删除

::: notes
集合（Set）也用花括号，但里面只有值，没有键。集合有两个特点：元素不重复、没有顺序。
重复的“可乐”自动只留一个。用 `set(列表)` 把列表转成集合，是最简单的去重方法。
因为没有顺序，集合不能用索引，`s[0]` 会报 `TypeError: 'set' object is not subscriptable`；打印出来的顺序也可能和写的时候不一样，每次运行都可能不同。需要有序时，用 `sorted(集合)` 转成排好序的列表。
集合常用的操作：`s.add(x)` 加入元素，`s.discard(x)` 删除元素（不存在也不报错），`x in s` 判断是否包含（比在列表里找快得多）。
:::

## 7.4.2 交集、并集、差集

- 比较周六和周日来店的会员

::: notes
集合最有用的地方是比较两组数据，就像数学里的韦恩图：
例如比较周六和周日来店的会员：`a & b` 是两天都来的“铁杆顾客”，`a - b` 是只周六来的，`a | b` 是整个周末来过的所有人。实验 7-3 会用一份虚构的名单试一试。

## 7.4.2 交集、并集、差集

| 运算 | 写法 | 含义 | `a = {1, 2, 3}`、`b = {2, 3, 4}` |
|---|---|---|---|
| 交集 | `a & b` | 两边都有的 | `{2, 3}` |
| 并集 | <code>a &#124; b</code> | 两边合起来（去重） | `{1, 2, 3, 4}` |
| 差集 | `a - b` | a 有、b 没有的 | `{1}` |
| 对称差集 | `a ^ b` | 只在一边有的 | `{1, 4}` |

::: notes
3.7 节说过，大模型先把文字切成一个个词元，再把每个词元换成一个编号。这个“词元 → 编号”的对照表，叫词表（Vocabulary），它本质上就是一个巨大的 Python 字典，例如 `{"你": 1234, "好": 5678, ……}`，常见大模型的词表有十几万个键值对。模型输出编号时，再用一个“编号 → 词元”的反向字典把它翻译回文字。
不仅如此，本章的词频统计也是 AI 处理文本的基础：在大模型出现之前，判断一条评价是好评还是差评、给新闻分类，很多方法都是先统计词频，再交给模型计算。即使在今天，构建词表的第一步，仍然是在海量文本上统计哪些字和词出现得最多。
你调用大模型接口时收到的回复（第 12 章），也是一个层层嵌套的字典，要用 `回复["choices"][0]["message"]["content"]` 这样的写法一层层取值。学好字典，这些都不难。
