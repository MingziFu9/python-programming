# 9.3 一维、二维数据与 CSV 文件

## 9.3.1 一维数据的存储

- 一行数据用逗号连起来：`",".join(列表)`
- 读回用 `split(",")`

::: notes
6.5 节说过，排成一行的数据叫一维数据，比如一周的营业额。存成文件时，最简单的方法是用逗号把它们连成一行，读回来时再按逗号拆开：
写的时候用 `join` 把列表连成字符串（数字要先转成字符串），读的时候用 `split` 拆开，再转回数字。
:::

## 9.3.2 CSV：二维数据的通用格式

- 每行一条记录，逗号分隔各列
- 第一行是**表头**
- Excel、WPS、pandas 都能打开

::: notes
把二维数据（表格）按“每行一条记录、每列用逗号隔开”存成纯文本，就是 CSV 文件（Comma-Separated Values，逗号分隔值）。本书的配套数据 `sales_2025.csv` 就是 CSV，用记事本打开，前三行是这样的：
第一行是表头（各列的名字），下面每行是一条销售记录。两个逗号挨着（`,,`）表示那一格是空的（这单没有会员号）。CSV 可以用 Excel、WPS 直接打开，也是数据分析、人工智能最常用的数据格式之一。
CSV 看起来简单，用 `split(",")` 好像就能拆开。但如果某一格的内容本身含有逗号（比如商品名“薯片,番茄味”），规则就复杂了。所以读写 CSV 要用 Python 自带的 csv 模块，它会自动处理这些情况。
:::

## 9.3.3 用 csv 模块读写

- 写：`csv.writer(f).writerow(一行)`，打开时加 `newline=""`
- 读：`csv.reader` 每行一个列表
- `csv.DictReader` 每行一个字典：`r["金额"]`
- 给 Excel 用：`encoding="utf-8-sig"`

::: notes
写 CSV：用 `csv.writer`，`writerow` 写一行（一个列表），`writerows` 写多行（二维列表）：
这里有两个新参数：`newline=""` 防止在 Windows 上每行之间多出一个空行；`encoding="utf-8-sig"` 是带“签名”的 UTF-8，它在文件开头加了一个标记，让 Excel 认出这是 UTF-8 文件，双击打开就不会乱码（3.6.3 节的问题由此解决）。
读 CSV 有两种方法：
`csv.reader` 把每一行变成一个列表，用索引取列。更方便的是 `csv.DictReader`，它把每一行变成一个字典，键就是表头，可以按列名取值：
`r["金额"]` 比 `row[8]` 好读得多，也不怕列的顺序变了。注意读出来的仍然都是字符串，计算前要 `float()`。实验 9-1 用 DictReader 读完全年 8437 行销售记录，按支付方式汇总金额。
:::

## 9.4 JSON 文件

- 存字典、列表嵌套的数据
- `json.dump` 写文件，`json.load` 读文件
- 带 s 的处理字符串：dumps、loads
- 中文加 `ensure_ascii=False`

::: notes
CSV 适合存放规整的表格。如果数据是“字典里有列表、列表里有字典”这样的嵌套结构（比如一位会员有好几个标签），用 JSON 更合适（7.3.2 节）。Python 自带 json 模块：
记忆方法：带 s 的处理字符串（string），不带 s 的处理文件。
默认情况下，中文会被转成 `\u59d3` 这样的编码，人看不懂；加上 `ensure_ascii=False`，中文就原样保存了。保存到文件时再加 `indent=2`，每层缩进 2 个空格，文件就整齐好读了，实验 9-3 会看到效果。
和 CSV 不同，JSON 能保留数据类型：存进去是数字 693，读回来还是数字，不用再转换。第 12 章调用大模型接口时，发送的请求和收到的回复都是 JSON，用的就是 `json.loads` 和 `json.dumps`。
:::

## 9.4 JSON 文件

| 函数 | 作用 |
|---|---|
| `json.dump(数据, f)` | 把字典、列表写入文件 f |
| `json.load(f)` | 从文件 f 读出数据，还原成字典、列表 |
| `json.dumps(数据)` | 把字典、列表转成 JSON 字符串 |
| `json.loads(字符串)` | 把 JSON 字符串还原成字典、列表 |

# 9.5 异常处理

## 9.5.1 什么是异常

- 运行时发生的错误叫**异常**
- 没有处理就会终止程序
- 语法错误不是异常，必须改代码

::: notes
程序运行时发生的错误，叫异常（Exception）。前面各章已经见过不少，这里汇总一下最常见的：
注意，`SyntaxError`（语法错误）和 `IndentationError`（缩进错误）不是运行时的异常，而是程序还没运行，Python 检查代码时就发现的错误，必须改代码，不能“处理”。附录 C 有完整的报错速查表。
异常一旦发生而没有处理，程序就会停止，并显示 Traceback。但有些异常是可以预料的：用户总会有输错的时候，文件总可能被人删掉。对这类情况，我们可以提前“接住”异常，让程序继续运行。
:::

## 9.5.2 try-except：接住异常

- 可能出错的代码放在 try 里
- 出错就跳到对应的 except
- `except ValueError:` 只接住这一种

::: notes
把可能出错的代码放在 `try` 里，把出错后的处理放在 `except` 里：
输入“两瓶”时：`int("两瓶")` 抛出 ValueError，try 里剩下的代码不再执行，程序跳到 `except ValueError:` 执行提示，然后继续往下运行，而不是崩溃。
`except` 后面写异常的类型，表示“只接这一种”。可以写多个 except，分别处理不同的异常；还可以用 `as e` 拿到异常的详细信息：
:::

## 9.5.3 else 与 finally

| 部分 | 什么时候执行 |
|---|---|
| `try` | 总是先执行；某一行出错，后面的行就跳过 |
| `except 类型` | try 中发生了这种类型的异常时 |

- try 里只放可能出错的几行

# 9.6 调试：找到并改正错误

## 9.6.1 读懂多层 Traceback

- 从上往下是调用的过程
- **最下面一层**是真正出错的地方
- 最后一行是错误类型

::: notes
1.6 节学过读报错的三步法：先看最后一行（什么错）、再看行号（哪里错）、最后看代码（为什么错）。当程序里有函数调用时，Traceback 会有好几层：
（路径中的“……”是编者省略的文件夹。）`most recent call last` 的意思是“最近的调用在最后”。从上往下读，就是程序一层层调用的过程：主程序（``）第 9 行调用了 report，report 第 6 行调用了 unit_price，unit_price 第 2 行做除法时出错。
所以，最下面一层是出错的地方，往上是“谁调用了它”。错误的原因常常不在最下面一层：除数 qty 为什么是 0？要往上找，原来是第 8 行的数据里面包的数量写成了 0。
:::

## 9.6.2 print 调试与断点

- print 输出中间结果
- Thonny 单击行号设**断点**
- 调试运行，停在断点处看变量

::: notes
有些错误不报错，只是结果不对（比如 4.5 节的条件顺序写反）。这时可以用两种方法：
print 调试：在可疑的地方临时加几行 print，把变量的值打出来看看，确认程序走到了哪里、变量是不是你以为的值。找到问题后记得删掉这些 print。
断点：在 Thonny 中单击某一行左边的行号，会出现一个红点，这就是断点。然后点“调试”（Ctrl + F5），再点“继续”（F8），程序会一直运行到断点这一行停下来，你可以在“变量”面板中查看所有变量当时的值，再用“步过”（F6）一行一行往下走。和 5.6.2 节的单步执行相比，断点可以直接跳到你关心的地方，不用从第一行开始一步步点。
:::

## 9.6.3 让 AI 帮忙查错的正确问法

- 给出：代码、完整报错、期望结果、你的尝试
- 先让 AI 解释原因，再让它改
- 改完自己运行验证

::: notes
第 1 章讲过 AI 编程助手的使用原则。查错时，AI 的帮助很大，但问法决定了答案的质量。对比两种问法：
最后一句很重要：先让 AI 解释原因，自己动手改，这样下次遇到同样的错误你就会了。另外，不要把真实的顾客姓名、手机号等个人信息粘贴给 AI，测试用虚构数据代替。
:::
